# 招标延期核对助手

采购代理人核对招标延期时，需要找回原公告与后续更正公告。本工具输入招标公告**列表页地址**，
沿同站点“下一页”自动抓取详情页，按字段标签读取项目编号、公告类型、发布时间、投标截止时间，
按**项目编号归并**、按**发布时间先后**处理，并在浏览器展示每个项目的当前结果与全部公告链接。

## 处理规则

按**项目编号归并**后，公告不再简单按单个时间点排序，而是先判断发布时间能否确定先后：

- 发布时间按文本精度展开为“可能发布时刻窗口”：仅标注日期的覆盖当天全天、
  只写到分钟的覆盖该分钟、写到秒的退化为时刻点；无法解析的视为时刻未知。
- 窗口相交/相接的公告属于**同批公告**，彼此先后无法确定，其裁决**不依赖抓取顺序**
  （调换列表页内同批公告的排列，归并结果不变）。

| 情形 | 处理结果 |
| --- | --- |
| 更正/延期公告**明确写出新的投标截止时间**，且明确晚于此前公告 | 用新时间**替换**旧时间，状态为“有效” |
| 较晚公告**声明延期却未给出新时间** | 状态标为 **“待核实”**，不再显示/沿用旧截止时间 |
| 同批公告（同分钟，或日期-only 与当天具体时刻混用）给出**相互冲突的截止时间** | 状态标为 **“待核实”**，不显示任何可用截止时间 |
| 同批公告中一条**声明延期却未给新时间**（即使同批另一条写了期限） | 状态标为 **“待核实”**，不显示任何可用截止时间 |
| 待核实之后，**发布时间明确更晚**的后续公告公布新截止时间 | 解除待核实，状态恢复 **“有效”**，采用新期限 |
| 同批公告给出的截止时间一致 | 不视为冲突，正常沿用该时间 |
| 所有公告均未公布截止时间 | 状态为“未公布” |
| 只有原始招标公告 | 沿用原截止时间，状态为“有效” |

同一项目的全部公告（原公告、更正、延期、澄清）按发布时间升序保留，并附原文链接；
发布时间精度不足或同批先后不明时，公告记录上会直接标注原因，便于回溯核对。

## 目录结构

```
.
├── docker-compose.yml          # 一键启动网页 + 同结构本地示例站点
├── webapp/                     # FastAPI 服务端渲染应用（Jinja2 模板）
│   ├── Dockerfile
│   ├── requirements.txt
│   └── app/
│       ├── main.py             # 路由：录入、结果页、页面代理
│       ├── crawler.py          # 列表页/下一页/详情页抓取（仅同站点）
│       ├── parser.py           # 按字段标签解析详情（表格/dl/label/正文兜底）
│       ├── merger.py           # 按项目编号归并、按发布时间精度（时间窗口）处理截止时间
│       ├── models.py
│       ├── utils.py             # 时间窗口/精度解析、文本清洗、同源判断
│       └── templates/index.html
├── example-site/               # 同结构本地示例站点（静态 HTML + nginx）
│   ├── Dockerfile              # 构建时运行 generate_site.py 生成页面
│   ├── nginx.conf
│   ├── generate_site.py        # 10 个项目、24 条公告、2 个列表页的场景数据（自包含）
│   └── site/                   # 生成产物（可重新生成）
└── tests/test_end_to_end.py    # 端到端测试（抓取 → 解析 → 归并 → 状态/精度/顺序无关断言）
```

## 用 Docker Compose 启动

```bash
docker compose up --build
```

- 网页应用：<http://localhost:8000>
- 示例站点（宿主机直连）：<http://localhost:8080>

在网页输入框中填入示例站点的列表页地址（容器内服务名地址，网页后端可直接抓取）：

```
http://example-site/list/page_1.html
```

点击“开始核对”后，页面展示：

1. 抓取概况：遍历的列表页（即“下一页”路径）、公告数、跳过链接、错误信息；
2. 各项目当前核对结果：项目编号、名称、状态徽章、**当前**投标截止时间；
3. 每个项目可展开的公告历史：公告类型、是否声明延期、发布时间、原文截止时间及链接。

> 公告链接默认指向容器内网地址（如 `http://example-site/...`），宿主机浏览器无法直接打开，
> 因此页面链接统一经过网页后端的 `/view` 代理打开；示例站点本身也映射在 8080 端口可直接浏览。

## 解析器的字段适配

详情页解析不绑定固定模板，按“字段标签 → 值”依次尝试：

1. 表格行（`th/td`，含一行两对字段）；
2. `dl/dt/dd` 定义列表；
3. `label` + 输入控件（`input/textarea/select`）；
4. 正文中的“标签：值”段落。

标签支持常见别名（如“招标项目编号/项目编码”“投标文件递交截止时间/开标时间”等），
标签缺失时再用正则兜底；识别不到项目编号的页面会被跳过并记入“跳过链接”。

## 安全与边界

- 仅跟随与入口**同站点**（协议+主机+端口一致）的“下一页”和详情链接，跨站链接跳过并记录；
- 只允许 `http(s)`，拒绝 `file://` 等协议；
- 上限：列表页 10 个、详情页 100 个、单请求超时 15 秒；
- `/view`、`/asset` 代理同样只转发 `http(s)` 目标。
